# KFC Football Club Web 제품 사양

## 1. 목적

친구 중심의 비공개 축구 모임 한 곳에서 회원, 일정, 참가 신청, 대기 순번, 출석과 월별 참석 현황을 관리한다.

별도 앱 설치 없이 Android, iPhone, 태블릿과 PC의 최신 브라우저에서 사용할 수 있어야 한다.

## 2. 사용자와 권한

- `owner`: 한 명. 클럽 설정, 초대 코드, 관리자 지정과 회원 관리 권한을 가진다.
- `admin`: 일정, 참가자, 출석과 공지를 관리한다.
- `member`: 일정 조회, 참가 응답, 본인 프로필 수정과 공개 현황 조회가 가능하다.

버튼을 숨기는 것만으로 권한을 구현하지 않는다. 데이터베이스 정책과 함수가 최종 권한을 검증한다.

## 3. 인증 정책

- 첫 버전은 Google OAuth만 제공한다.
- Kakao OAuth는 핵심 흐름 안정화 후 추가한다.
- 인증 제공자의 사용자 ID를 계정 식별 기준으로 사용한다.
- 이메일은 연락 정보이며 고유 계정 키로 사용하지 않는다.
- 서비스 역할 키와 OAuth 비밀값은 정적 사이트에 포함하지 않는다.

## 4. 첫 운영 버전 범위

1. Google 로그인과 로그아웃
2. 이름 또는 닉네임, 나이, 프로필 사진과 선택 프로필
3. 고정 초대 코드로 클럽 가입
4. owner, admin, member 권한
5. 이벤트 생성, 공개, 수정과 취소
6. 참가, 불참, 선착순 확정과 대기 등록
7. 확정 취소 시 대기 1순위 자동 승급
8. 참가, 대기, 불참과 미응답 명단 공개
9. 관리자의 출석 체크와 회원 공개
10. 공지사항
11. 월별 참석 횟수

## 5. 첫 운영 버전 제외

- App Store와 Play Store 네이티브 앱
- 푸시 알림과 앱 내 알림함
- 팀 편성, 포메이션, 득점과 경기 결과
- 결제, 회비 장부와 입금 확인
- 사용자 화면의 다중 클럽 전환
- Kakao 로그인

## 6. 핵심 운영 정책

- 초대 코드가 맞으면 승인 없이 가입한다.
- 첫 화면에서는 사용자당 활성 클럽 하나만 허용한다.
- 참가와 대기는 서버 접수 순서로 정한다.
- 공식 시각은 데이터베이스 서버 시각을 사용한다.
- 신청과 취소 마감을 서버에서 판정한다.
- 마지막 자리 신청, 취소와 자동 승급은 하나의 트랜잭션으로 처리한다.
- 일반 회원은 역할, 공식 카운트, 순번과 감사 기록을 직접 수정할 수 없다.
- 취소된 일정과 취소 사유는 owner와 admin만 조회한다.

## 7. 웹 UX 원칙

- 모바일 화면을 우선하되 320px부터 데스크톱까지 대응한다.
- Hash 기반 화면 전환을 사용해 GitHub Pages의 하위 경로 새로고침 문제를 피한다.
- 로그인 전에는 서비스 소개와 로그인만 제공한다.
- 로딩, 빈 상태, 오류와 권한 부족 상태를 화면마다 제공한다.
- 키보드만으로 모든 기능을 사용할 수 있어야 한다.
